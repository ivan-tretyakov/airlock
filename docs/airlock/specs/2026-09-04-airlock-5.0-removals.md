# Airlock 5.0 — Removals and Release

- Date: 2026-09-04
- Status: ready-for-agent
- Series: Airlock 5.0, spec 3 of 3. Depends on spec 2 (`2026-09-04-airlock-5.0-run.md`) being merged; spec 1 should also be merged so the README describes the final state once.
- Decided in: grill-me session 2026-09-04 (Q1, Q13, Q14, Q23)

## Problem Statement

After the runner exists there are two dispatch paths: the host subagents rendered from the role files, and `airlock run`. Two paths mean the role text can drift, the OpenCode bootstrap and its hash-guarded shims exist only to serve the path nobody uses, and the Herdr extension is a dozen source files plus tests and specs for a Linux-only pane-driving design that was abandoned. The README still describes all of it.

## Solution

Delete everything that served host-side dispatch: the Herdr extension and its specs, the OpenCode bootstrap and adapters, the `--host` flag, the bundled Claude role agents, and the `render` support for host agent files. Rewrite the README around the runner. Release as 5.0.0, a breaking version. Give the operator a checklist to remove the generated agent files left on their machine by 3.x.

## User Stories

1. As a maintainer, I want one dispatch path, so that the role text lives in exactly one place.
2. As a maintainer, I want the Herdr extension gone, so that the repository carries no code for a design that was rejected.
3. As a maintainer, I want the OpenCode bootstrap gone, so that `init` has no host branch and no shim hash guards.
4. As a maintainer, I want `--host` removed rather than deprecated, so that no accepted-and-ignored flags remain.
5. As a maintainer, I want the plugin to ship only the command and the CLI, so that no host agents are registered that the runner never uses.
6. As a user, I want the README to describe the runner-first workflow, so that a new reader is not sent to agent files that do not exist.
7. As a user, I want a 5.0.0 release with a migration note, so that I know why my `init --host opencode` stopped working and what to do instead.
8. As a user, I want a checklist for cleaning up my machine, so that stale generated agents from 3.x do not confuse my executors.
9. As a maintainer, I want the test suite to lose only the tests for deleted behaviour, so that coverage of the surviving core is unchanged.
10. As a maintainer, I want the package `files` list to match what remains, so that the published package does not reference deleted paths.
11. As a maintainer, I want the specs of removed subsystems archived, not deleted, so that the reasoning stays findable.

## Implementation Decisions

- Delete: the Herdr extension directory, the OpenCode adapter directory, the empty guard-canary directory, the OpenCode command fixtures, the OpenCode bootstrap code in `init`, the `--host` flag on every verb, the agent-file rendering in `render`, and the `agents` list in the plugin manifest.
- Keep: the three role files, which the runner reads; `render --md` for the plan table; the `/airlock` command file as rewritten by spec 2.
- Move the Herdr adapter and router specs and their reviews to the archive directory under a `2026-09` folder, following the existing archive layout. Do not delete them.
- README: rewrite the Hosts and Extensions sections into one "Running" section that describes `airlock run`, the routing file, the initial routing table, the `EVIDENCE:` contract, the failure policy, and the model-session driving pattern from a terminal in a worktree. Update the Quick Start, the Plan File location, and the description line to drop "for Claude Code and OpenCode". Remove every mention of host agent files, `--host`, and Herdr.
- Package: version 5.0.0 in both manifests; `files` lists the CLI, the roles, the command, README, and LICENSE; description becomes "Plan-driven multimodel task orchestration with headless executor dispatch".
- Release note at `docs/airlock/releases/5.0.0.md`: what was removed, the plan location change from spec 1, the routing file, and a migration paragraph for 4.x users: install the CLI globally from the tag, write the routing file, remove any `.opencode/agent/airlock-*.md` and `.opencode/command/airlock.md` a 4.x bootstrap wrote into their projects.
- Operator checklist in the same release note, not automated: delete the generated `airlock-*` agent files in the user-level OpenCode agents directories and in the user-level Claude agents directory, and remove the 3.x fallback backup of the OpenCode config if it is no longer wanted.

## Testing Decisions

- The seam is unchanged. Remove the tests named for OpenCode bootstrap, shim upgrade, customized agent preservation, and `--host` acceptance. Add one test that `--host` is rejected as an unknown flag on `init`, and one that `render --md` still prints the role column. Every surviving test must pass unchanged.
- A good test here is a negative one: after the deletion, `npm test` passes, `npm pack --dry-run` lists no deleted path, and a grep for `host`, `herdr`, `.opencode` across the package finds only the archive and release note.

## Out of Scope

- Any change to `run`, routing, or the plan-state rules from specs 1 and 2.
- Touching the operator's machine. The checklist is text.
- The Buynomics plugin.
