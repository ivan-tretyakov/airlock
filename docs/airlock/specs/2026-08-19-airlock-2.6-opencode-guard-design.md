# Airlock 2.6 - OpenCode Full Guard

**Status:** approved implementation input (user-commissioned, 2026-08-19).
**Baseline:** Airlock 2.5 merged as PR #4 (`00d6200`).
**Scope:** enable Full Airlock orchestration on OpenCode only when an OpenCode plugin mechanically applies the existing `airlock.contract/v2` guard.

## Decision

Use OpenCode's `tool.execute.before` plugin hook to normalize its write-capable tools into the existing `hooks/guard.mjs` input format. The existing guard remains the canonical policy engine; the adapter owns only OpenCode tool and session translation.

## Enforcement

- `edit`, `write`, `apply_patch`, `bash`, and `task` pass through the adapter.
- OpenCode runs plugins under Bun, so the adapter invokes the canonical guard through `node`/`node.exe`, never the plugin host's `process.execPath`.
- Contract validity and expiry are shared with `hooks/guard.mjs`; `single-actor` applies worker scope without session attribution.
- The configured OpenCode shell selects the guard analyser: PowerShell/pwsh use `PowerShell`; bash/sh/zsh/dash/ksh use `Bash`; unsupported shells block Full work.
- `apply_patch` checks every add, update, delete, and move path before execution. Ledger patches are denied because they cannot support deterministic checkpoint simulation; use `edit` or `write`.
- Root OpenCode sessions are the orchestrator; sessions with a parent are workers. An unresolved actor under an active valid v2 contract is denied.
- A valid active contract fails closed through the existing guard. Missing, malformed, or expired contracts retain the existing fail-open compatibility behavior, except global ledger hygiene.
- The adapter does not claim hostile-process containment or MCP-side-effect sandboxing.

## Host Gate

Claude Code qualifies through its PreToolUse guard. OpenCode qualifies only when `airlock_guard_status` is available and reports `fullCapable: true`. Hosts without either mechanism remain blocked for Full work.

## Validation

Unit tests cover root/worker scope, broad staging, nested tasks, mixed-scope patches, ledger patches, and missing actor attribution. A disposable OpenCode canary proves the plugin denial still holds under `--auto`.

## Harness divergences

- `apply_patch` never changes ledger files; use `edit` or `write` for content-aware ledger hygiene.
- Missing Node, a guard subprocess failure, or an unsupported shell fail closed for guarded OpenCode work. Invalid, expired, or absent contracts retain the canonical fail-open compatibility behavior.
- Coverage is limited to `edit`, `write`, `apply_patch`, `bash`, and `task`; future mutating tools require an explicit adapter update.
- Windows and Linux must each complete the live canary before release. Linux validation is a post-pull gate for this release branch.

## Out of Scope

Plugin-order adversarial defense, automated global installation, per-worker parallel contracts, new contract schemas, and MCP-side-effect containment.
