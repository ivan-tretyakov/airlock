- Status: ready-for-agent

- Decided in: grill-me session 2026-09-04 (Q2, Q3, Q4, Q8, Q11, Q14, Q15, Q16, Q18, Q19, Q20)
- Replaces: the Herdr router (`2026-09-01-airlock-herdr-router.md`) as the multi-executor dispatch path

## Problem Statement

Today a Claude Code or OpenCode session drives `/airlock` and spawns a subagent per task. The driving session pays for every task's context relay, it can only use the models its host offers, and one subscription plan is not enough for a day of building. The Herdr router solved executor mixing but is Linux-only and drives interactive panes, which needed correlation records, nonces, timeouts, and reconciliation to know when a task ended.

## Solution

One CLI verb, `airlock run`, executes the next runnable task end to end: it calls `next` and `start`, assembles the worker prompt from the role body and the task brief, spawns the chosen executor CLI headless, waits for exit, parses one `EVIDENCE:` line from the worker's output, then runs `audit` and `done` or `block`. Which executor, model, and effort a task gets is a flat lookup by role and tier in `~/.airlock/routing.json`. By default one invocation does one task, so a model session can steer between tasks; `--all` loops until nothing is runnable.

## User Stories

1. As a developer, I want one command that takes the next task from the plan to a commit, so that I never relay a brief by hand.
2. As a developer, I want each task to run in a fresh process with only its brief, so that my driving session's context stays clean.
3. As a developer, I want builders on a subscription other than my Claude plan, so that a day of building does not exhaust it.
4. As a developer, I want checkers on a different vendor than builders, so that a model never grades its own work.
5. As a developer, I want expensive tasks on the strongest model, so that irreversible work gets the best judgement.
6. As a developer, I want the routing to be one flat file with six slots, so that changing a model is a one-line edit.
7. As a developer, I want the runner to fail closed on a missing routing slot, so that a task is never sent to a guessed model.
8. As a developer, I want `run` to do one task by default, so that I can edit the plan between tasks from a model session.
9. As a developer, I want `run --all` to loop unattended, so that a proven plan finishes without me.
10. As a developer, I want a failed or stalled executor to block the task and stop the run, so that a quota problem does not burn through the remaining tasks.
11. As a developer, I want a per-task timeout, so that a stuck worker cannot hold the run forever.
12. As a developer, I want the worker's evidence to become the `done` evidence, so that the commit records what was actually verified.
13. As a checker author, I want a failing check to block the task with the findings location as reason, so that a driver knows to add fix tasks.
14. As a developer, I want the runner to print one line per task, so that I can follow a run from a terminal tail.
15. As a developer, I want the runner to stop cleanly at `PARKED`, `NOTHING TO DO`, or `BUDGET REACHED`, so that the existing decision flow is untouched.
16. As a developer, I want the role bodies read from the package, so that there is one source of role text and no agent files to install.
17. As a developer, I want a dry-run that prints the resolved executor command without launching it, so that I can check a routing edit safely.
18. As a developer, I want `run --json` for scripting, so that a driver session can read the result without parsing prose.

## Implementation Decisions

- New coordinator verb `run`, flags `--all`, `--dry-run`, `--json`, `--plan`, `--routing <path>`. Default routing path is `~/.airlock/routing.json`. The verb is part of the existing CLI, not a second package.
- Routing schema, version 1, `bindings.<role>.<tier>` with `role ∈ {builder, checker, browser}` and `tier ∈ {default, expensive}`, each slot exactly `{ executor, model, effort? }` with `executor ∈ {claude, codex, opencode}`. Optional top-level `timeoutMinutes` (default 30). Unknown keys anywhere are rejected. No windows, fallbacks, pins, or catalog. A missing slot for the selected role and tier fails closed with the exact JSON path named. Tier is `expensive` if the task has `expensive: true`, else `default`; there is no tier inheritance.
- The initial routing table for this machine, to be written by the operator, not the code:

| role | default | expensive |
|---|---|---|
| builder | opencode · zai-coding-plan/glm-5.3 · high | claude · opus · high |
| checker | codex · gpt-5.6-sol · medium | codex · gpt-5.6-sol · high |
| browser | codex · gpt-5.6-sol · medium | claude · opus · high |

- Worker prompt is the role body from `roles/<role>.md` with its frontmatter stripped, then a blank line, then the `TASK` brief exactly as `next` printed it, then the output contract sentence: the last line of your output must be `EVIDENCE: PASS <command and result>` or `EVIDENCE: FAIL <reason or findings path>`. The role body gains that sentence permanently so the contract is stated in one place; the runner appends nothing else.
- Executor invocations, all with the current directory set to the repository root and the prompt passed on stdin or as the final argument as each CLI requires:
  - claude: print mode, `--model`, `--effort` when set, `--permission-mode bypassPermissions`, prompt as argument.
  - codex: `exec`, `-m`, `-c model_reasoning_effort=<effort>` when set, `--dangerously-bypass-approvals-and-sandbox`, `--skip-git-repo-check`, last message captured through the output-last-message flag.
  - opencode: `run`, `-m`, `--variant <effort>` when set, `--auto`, prompt as the message argument.
  - The runner does not alter the inherited environment. Orca's injected `CODEX_HOME` and `OPENCODE_CONFIG_DIR` are left in place; `CLAUDE_CODE_SUBAGENT_MODEL` is stripped as the router did.
- Evidence parsing: the last non-empty line of the worker's final message must match `^EVIDENCE: (PASS|FAIL) (.+)$`. `PASS` leads to `audit` then `done --evidence "<rest>"`. `FAIL` leads to `block --reason "<rest>"`. A missing or malformed line is a `FAIL` with reason `worker returned no EVIDENCE line`.
- Failure policy: non-zero exit, spawn error, missing binary, or timeout blocks the task with the cause as reason and ends the run, in both single and `--all` mode. Nothing retries and nothing falls back. An `audit` failure blocks with the audit text, as `/airlock` does today.
- Sequencing in `--all`: one worker at a time. `--parallel` dispatch is not used by the runner.
- `run` stops with the same texts and exit codes the underlying verbs produce: `PARKED` (exit 2 under `--unattended` semantics, which `run` always uses), `NOTHING TO DO`, `BUDGET REACHED`. In single mode the result line is `RAN <id> DONE <commit>` or `RAN <id> BLOCKED <reason>`.
- `--dry-run` resolves routing and prints the assembled command line and prompt length without calling `start`.
- The `/airlock` command file becomes: run `airlock run`, show the line, if `PARKED` or `NOTHING TO DO` present decisions as today, else repeat. It never dispatches a subagent. The plugin still bundles the CLI through the plugin root.

## Testing Decisions

- Same seam as the rest of the suite: spawn the CLI in a temporary git repository and assert on output and git state. The executors are faked by putting scripts named `claude`, `codex`, and `opencode` on a temporary PATH entry ahead of everything else, with `.cmd` shims on Windows. Each fake records its argv and stdin to a file and prints a scripted final message. No new seam and no mocking inside the module.
- Tests: routing file validation rejects unknown keys, unknown executors, and a missing slot with the JSON path named; each executor receives the expected flags for model and effort; the prompt handed to the fake contains the role body and the exact brief; a `PASS` worker yields an audited commit whose evidence trailer equals the worker's text; a `FAIL` worker yields a blocked task with the reason; a missing `EVIDENCE:` line blocks; a non-zero exit blocks and `--all` stops after it; a fake that sleeps past a one-second `timeoutMinutes` fraction blocks with a timeout reason; `--all` completes a two-builder plan in dependency order and stops at `NOTHING TO DO`; `--dry-run` launches nothing.
- Prior art: the fixtures in the Herdr router tests for executor flag assembly, before they are deleted in spec 3; the CLI cycle tests in the main suite.

## Out of Scope

- Deleting the Herdr extension, hosts, and bootstrap (spec 3).
- Any pane-driving, Orca, or Herdr integration.
- Fallback chains, time windows, pinning, or model catalogs.
- Parallel workers.
- Installing skills or agent files into any executor's home.
- The Buynomics review skill and its findings contract beyond the `EVIDENCE: FAIL <path>` line.

## Further Notes

The quota motive means the most likely runtime failure is a rate limit on one vendor. The stop-the-run policy is deliberate: the operator edits one routing slot and reruns, rather than the runner silently draining a second subscription.
