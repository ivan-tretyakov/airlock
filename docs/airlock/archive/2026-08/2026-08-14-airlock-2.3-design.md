# Airlock 2.3 — Design Specification

**Status:** approved design input (user-commissioned, 2026-08-14) — implementing session runs `/airlock:plan` from this spec; `brainstorm` is satisfied by this document.
**Baseline:** Airlock 2.2 as merged from PR #1 (`codex/airlock-2.2`). All file references are against that tree.
**Sources:** private Airlock 2.1 session review (rev. 3, findings F1–F12; not published), PR #1 review comments (2026-08-14), and private unattended-operation/Linux-box notes.

## 1. Problem statement

2.2 fixed enforcement and interaction quality. Four gaps remain, one of them new:

1. **Ceremony doesn't scale down.** Every non-trivial task pays for specialist dispatches (investigate → code-* → verify → review), even when one competent agent could do investigate+implement+verify in a single contract. Concretely: releasing Airlock 2.3 itself currently classifies as **Full**, because `start.md:51` forces Full for "external publication" — although a release PR merged by the user already contains its human gate. A version bump should not cost 6+ dispatches.
2. **Browser agents re-authenticate every run** (F12). Root cause identified: Playwright MCP segregates profiles by workspace hash, and Airlock's worktree-per-lane means every lane gets a fresh logged-out profile; chrome-devtools-mcp launches its own profile unless pointed elsewhere. `/airlock:setup` bootstraps nothing today.
3. **Unattended runs stall at the first DECISION.** 2.2's interaction contract (correctly) turns unavailable `AskUserQuestion` into BLOCKED — which in a Routine/headless run means the night is wasted after one question.
4. **PR #1 review follow-ups** were acknowledged but not implemented (agent_id fallback, read-only-dispatch contracts, archive-not-delete, `.gitattributes`, two nits).

## WS-A — Adaptive ceremony

### A1. New multipurpose leaf: `agents/worker.md`

```yaml
name: worker
description: Multipurpose leaf for Compact and low-risk Full work; investigates, implements, and self-verifies within one contract.
model: sonnet
tools: [Read, Glob, Grep, Bash, PowerShell, Edit, Write, NotebookEdit, WebFetch, WebSearch]
```

Body mirrors `code-standard.md` (leaf rules, contract binding, STOP rule, artifact cleanup, post-GREEN simplify, return contract) **plus**: "You may investigate, implement, and verify within your contract in one run. State what you verified and how; distinguish verified from assumed. You cannot review your own work — independent review, when required, is a separate dispatch."

Cost note in the body: worker replaces an investigate + code-* + verify *sequence*, not the independent `review` gate.

### A2. Dispatch budgets (add to `commands/start.md` Classify, `orchestrator.md`)

| Workflow | Default execution | Dispatch budget (guideline) |
|---|---|---|
| Quick | inline or one `code-light`/`code-standard`/`worker` | 0–1 |
| Compact | one `worker` | 1–2 (worker + optional independent verify when risk-relevant) |
| Full-lite | `worker` per Crossing + only required gates | ≤3 per Crossing |
| Full | specialist leaves as planned | as planned |

Rules: prefer `worker` over investigate→code→verify chains unless (a) the investigation output is a user decision input, (b) the work class is Critical, or (c) a gate requires independence. Exceeding the budget is allowed but must be stated in one PROGRESS line with the reason. Specialist leaves (`investigate`, `verify`, `code-complex`, `code-critical`) remain the right choice for Critical work and genuinely separable phases.

### A3. Release lane (edit `start.md:51`, `orchestrator.md:30`, README)

Replace the blanket "external publication … always uses Full" with:

- **Publication = directly mutating what users consume** (pushing a tag consumers auto-pull, publishing to a marketplace/registry, deploying): the *mutating step* always requires an explicit DECISION approval, but the surrounding work classifies on its own merits.
- **A release PR merged by the user is Compact by default**: version bumps, changelog, validation runs, opening the PR. The user's merge is the approval gate; Airlock does not duplicate it with a Full pack.
- Template the release flow in `PROJECT-CONVENTIONS.template.md`: bump versions (plugin.json + marketplace.json) → update changelog/README → run the three test suites + `claude plugin validate --strict` (both manifests) → branch + PR (DECISION: link) → after user merge, tag/publish only behind a second DECISION.
- Escalation still applies: a release that includes migrations, credential changes, or irreversible external state remains Full.

Acceptance for WS-A: "release Airlock 2.3" classifies as Compact, executes with ≤2 dispatches plus one DECISION for the PR, and `plugin-policy.test.mjs` gains assertions for the worker agent file and the revised classification text.

## WS-B — Project bootstrap (`/airlock:setup` v2)

### B1. Rewrite `commands/setup.md`

`/airlock:setup [native|opencode]` becomes an interactive bootstrap (all steps idempotent; re-running reconciles):

1. Runtime preference (existing behavior, kept).
2. **Browser backend**: detect/ask for exactly one (`playwright` | `chrome-devtools` | `none`). One per project — mixed backends across sessions was an observed failure source.
3. **Write project `.mcp.json`** (create or merge; on conflict show diff, never silently overwrite) wiring the chosen backend with the flags from B2. Project scope so every session and subagent inherits identical tools.
4. **Auth setup**: create `~/.airlock/auth/<project-slug>/` (outside repo, outside all worktrees). Print the one-line human login command; wait for the user to run it; verify the state file exists.
5. **Config v2**: extend `.airlock/config.json`:

```json
{
  "schema": "airlock.config/v2",
  "runtime": "native",
  "browser": {
    "backend": "playwright",
    "appUrl": "https://…",
    "authState": "<absolute path>/state.json",
    "authSignal": { "url": "…", "selector": "…" },
    "refreshCommand": "npx playwright open --save-storage=<path> <appUrl>"
  }
}
```

v1 configs remain valid (runtime only); guard and commands treat missing `browser` as "no browser gates configured".

6. **Preflight** (also runs at `/airlock:start` whenever the task/plan contains a browser gate): backend reachable ✔/✘, auth signal passes ✔/✘. On ✘ → BLOCKED with the exact `refreshCommand`. One line of output either way.
7. `.gitignore` check: warn if the auth path is inside the repo (it should never be); never add state files to `ownedPaths`/`processPaths`.

### B2. Backend flag policy

| Backend | Flags written to `.mcp.json` | Why |
|---|---|---|
| playwright | `--storage-state <authState>` (+ project-agreed viewport); **never `--isolated`, never default profile** | Storage state is parallel-safe (fresh context per run, cookies copied in); defeats workspace-hash segregation across worktrees |
| chrome-devtools | `--user-data-dir <authState-dir>/profile` **or** `--browserUrl http://127.0.0.1:9222` per user choice | Profile persists login; browserUrl attaches to the user's own logged-in Chrome (single-instance only) |

### B3. Harness awareness (Claude Code and OpenCode)

Setup must ask (or detect) which harnesses this project uses — `claude`, `opencode`, or both — and register the browser MCP for **each selected harness**, because registration is not shared:

| | Claude Code | OpenCode |
|---|---|---|
| Config file | `.mcp.json` at project root | `opencode.json` / `opencode.jsonc` at project root |
| Shape | `{"mcpServers": {"<name>": {"command": "...", "args": [...], "env": {...}}}}` | `{"mcp": {"<name>": {"type": "local", "command": ["exe", "arg", ...], "enabled": true, "environment": {...}}}}` — note `command` is an **array**, env key is `environment` |
| Subagent inheritance | project scope reaches sessions and subagents (the F2 answer) | tools flow through OpenCode's own agent config; the external `airlock-worker` denies undeclared tools via `OPENCODE_PERMISSION` — browser MCP is for *primary/host* OpenCode sessions, never injected into launcher-managed external workers |
| Detection | `commands/*.md` running ⇒ Claude Code | adapter commands (`.opencode/command/airlock-*.md`) running ⇒ OpenCode; `.airlock/config.json` records the selected set either way |

Rules: same server name (`browser`), same backend, same flags, same `authState` path in both registrations — one login serves both harnesses since the *browser process*, not the harness, loads the state. Merge-don't-overwrite applies to both files (on conflict: show diff, stop). The external-runtime contract is untouched: launcher-run workers keep their closed tool policy; WS-B only provisions interactive/host sessions.

### B4. OS awareness (Windows, Linux, macOS)

Setup detects the OS and adjusts four things; everything lands in config as **absolute paths and exact commands**, so downstream prompts never re-derive them:

| Concern | Windows | Linux / macOS |
|---|---|---|
| Auth home | `%USERPROFILE%\.airlock\auth\<slug>\` | `~/.airlock/auth/<slug>/` |
| npx-based stdio MCP launch | wrap for the shell where required — Claude Code on native Windows needs `"command": "cmd", "args": ["/c", "npx", "-y", ...]`; OpenCode `command` array should name the real executable (`npx.cmd`), since PowerShell/npm shims are exactly what the 2.2 launcher refuses | plain `npx -y …` |
| `refreshCommand` | emit a PowerShell-pasteable line | emit a bash-pasteable line |
| chrome-devtools specifics | default profile under `%HOMEPATH%`-side cache; `--executablePath` may be needed for non-standard Chrome installs | default under `~/.cache/chrome-devtools-mcp/`; macOS Chrome path differs — record `executablePath` in config when detected off-default |

Preflight (B1 step 6) validates the *stored* commands on the *current* OS — a config written on Windows and reused from the Linux box must fail loudly with "re-run /airlock:setup on this host", not half-work: add `"host": {"os": "...", "machine": "<hostname>"}` to config v2 and compare at preflight. Multi-machine projects (Windows laptop + Linux box) get per-host overlay files `.airlock/config.<hostname>.json` for the `browser` block only; base config keeps the harness/runtime choice.

### B5. Agent-side rules (already mostly in 2.2)

`browser-verify`/`visual-review` preflight the auth signal before evaluating flows (exists) — add: "On auth failure, return BLOCKED including the configured refreshCommand verbatim." The agent never reads or prints the state file; the browser process loads it.

Acceptance for WS-B: fresh repo → `/airlock:setup` → one human login → two consecutive browser-gate dispatches in different worktrees pass auth preflight with no manual login; expired state produces BLOCKED + refresh command. Harness/OS matrix: with both harnesses selected, `.mcp.json` and `opencode.json` both carry the `browser` server with identical backend/flags/authState; setup on Windows produces the `cmd /c` (Claude) and `npx.cmd` (OpenCode) launch forms; a config created on one host, used on another, fails preflight with the re-run message rather than half-working.

## WS-C — Unattended mode

### C1. Activation

`/airlock:start --unattended <task>`, or auto-detected when `AskUserQuestion` is unavailable. State it in the classification line: `Airlock: <weight>, native, unattended.`

### C2. DECISION parking (changes `start.md` Interaction contract, `orchestrator.md`, `review.md`)

In unattended mode, DECISION does not emit BLOCKED-and-stop. Instead:

1. Append a decision record to `docs/airlock/DECISIONS.md`: `| ID | Asked | Question | Options (2–4) | Recommendation | Blocks | Status |` with `Status: open`.
2. Mark the affected work package `blocked-on-user` in STATUS.md.
3. **Continue with the next unblocked package.** Stop entirely only when no unblocked work remains or the budget (C4) is exhausted.
4. When a Git remote surface exists, mirror the record as a PR comment (options numbered) — but the file is the source of truth.

At every session start (attended or not): read DECISIONS.md **first**; for each row with a user answer (`decision: <option>` edit or PR reply), record the approval in the ledger as if given interactively, set `Status: answered`, unblock the package.

### C3. Hard stops (never parked past, never auto-proceeded)

Design approval for new scope, anything in the always-Full safety list, merges to main, and the publication DECISION from WS-A3. These park and *end the affected lane*; they are the last item in the run summary.

### C4. Budget guard

Unattended runs declare a budget at start: max Crossings (default 5) and/or max wall-clock. On exhaustion: refresh STATUS + ledger checkpoint, write the run summary (below), exit cleanly.

### C5. Run summary

Last act of every unattended run — replace-in-place `## Last unattended run` section in STATUS.md: `Completed | Parked decisions (IDs) | Blocked | Budget used | Next action`. Five lines maximum.

Acceptance for WS-C: a scripted headless run (`claude -p … --permission-mode dontAsk`) over a plan containing one deliberate decision point completes the other packages, produces a well-formed DECISIONS.md row, and a follow-up attended session picks up the answer and unblocks.

## 3. Cross-cutting requirements

- **Tests:** every prompt-text change gets a matching `plugin-policy.test.mjs` assertion update; guard changes get `guard.test.mjs` cases (actorMode fallback, minimal read-only contract, config v2 parse). All three suites green on Windows before the release PR; note the external-agent suite's known Linux-environment failures separately.
- **Docs:** README sections for worker agent, release lane, setup v2, unattended mode; glossary additions (`worker → all-round builder`, `DECISIONS.md → questions waiting for you`).
- **Version:** 2.3.0 in `plugin.json` + `marketplace.json`.
- **Dogfood:** release 2.3 using the WS-A release lane itself — it is the acceptance test for A3.
- **Out of scope for 2.3:** per-worker parallel contracts (D6 design note only), OpenCode external-runtime changes, porting to Managed Agents.

## 4. Risks

| Risk | Mitigation |
|---|---|
| `actorMode` fallback weakens enforcement if misconfigured | Default unchanged (`agent-id`); `single-actor` documented as degraded-host mode; smoke test in D1 is a release gate |
| `.mcp.json` merge conflicts with user's existing config | Never overwrite; show diff and stop (same rule setup already uses for config conflicts) |
| Decision parking silently starves a lane (F5 recurrence) | Parked decisions appear in STATUS *Open items* with age, and in every run summary — same aging machinery review.md already enforces for MUST_FIX |
| Worker agent quality < specialist chain on hard tasks | Budgets are guidelines with a stated-escalation path; Critical work keeps specialist routing unconditionally |
