# Airlock 2.4 — Design Specification: Right-size, Enforce, Measure

**Status:** approved design input (user-commissioned, 2026-08-17) — implementing session runs `/airlock:plan` from this spec; `brainstorm` is satisfied by this document.
**Baseline:** Airlock 2.3 on `main` (PR #2 merged, incl. review-fix `cf2ce15`).
**Sources:** W32–W33 usage audit (~540M OpenAI tokens; 152M opencode orchestrator session; dashboard-widgets ledger 2,923 lines / ~48K tokens with 68 Resume-checkpoint sections against a replace-in-place template of 1); external assessment (2026-08-17); session-evidence review `docs/airlock-review-2026-08-13` (F1–F12); launcher inspection (4,772 lines: byte bounds + 24h wall-clock exist, **no turn/tool-event cap**; external runtime used 5× / 24K tokens total).

## 0. The decision this release encodes

Airlock is a **Full-work tool**, not a way of working. Three findings force this:

1. The most productive sessions never invoked it; prototype work doesn't need contracts or evidence trails.
2. The token blowup came from running Full ceremony inside mega-sessions — and the worst case (68 appended checkpoints, 48K-token ledger re-sent every turn at 96% cache-read) happened in an **OpenCode-hosted** orchestrator session, where the guard hook — a Claude Code mechanism — **does not run at all**. The explosion occurred precisely where enforcement doesn't exist, not where it failed.
3. What Airlock enforces mechanically (paths, dispatch, staging) held; what it enforces by prose (ledger hygiene, checkpoint replacement, session budgets) dissolved under load. 2.4's theme: convert the surviving prose rules to mechanism, delete cost that buys nothing, and measure the result.

### Usage policy (goes in README + PROJECT-CONVENTIONS.template.md)

| Work type | Harness | Process |
|---|---|---|
| Prototype / throwaway / exploration | any harness, any model | **No Airlock.** Don't invoke `/airlock:start`. |
| Contained real change | either harness | Compact: one `worker`, 1–2 dispatches, no durable artifacts |
| Full / irreversible / production | **Claude Code host only** (guard active). OpenCode participates as dispatched external *worker*, never as Full orchestrator | Full, with the 2.4 enforcement below |

Rationale line for the README: OpenCode-hosted sessions have no PreToolUse guard, so every Airlock guarantee there is prose-only; Full work belongs where the mechanism exists. (Porting a guard equivalent to OpenCode plugin hooks is explicitly **deferred** — revisit only if OpenCode-hosted Full work is actually wanted.)

## WS-1 — Ledger and context discipline (highest value; helps BOTH token pools)

### 1a. Mechanical ledger hygiene (guard.mjs + tests)

Deny-only, same philosophy as contract v2 — the hook never mutates files:

- **Write** to a path under `docs/airlock/ledger/` (or matching the configured ledger glob): count `## Resume checkpoint` headings in `tool_input.content`; **deny at >1** with "replace the checkpoint in place; do not append".
- **Edit** to a ledger path: if `new_string` introduces a `## Resume checkpoint` heading, `old_string` does not contain one, and the on-disk file already has one → deny (hook may read the file; milliseconds).
- **Hard cap:** ledger file exceeding ~800 lines → deny all further ledger writes with "archive `## Completed` blocks to docs/airlock/archive/ first". Forcing the cleanup, not performing it.
- Archiving itself is a **`ship` close-out step** (prompt rule): when the ledger passes ~500 lines at pack acceptance, move `## Completed` blocks to `docs/airlock/archive/YYYY-MM/<work-id>-completed.md` and leave one-line references.
- Tests: guard.test.mjs cases for all four behaviors; fail-open preserved for non-ledger paths and malformed input.

### 1b. Bounded ledger reads (prompt change: ship.md, review.md, orchestrator.md, compact hook text)

Replace every "read the ledger" instruction with: read the **single Resume checkpoint + the sections named in it** (active pack, open gates). Full-ledger reads only on explicit repair/reconstruction. The compaction reminder text updates to match.

### 1c. Prompt slimming

- Extract shared lifecycle/gate/checkpoint prose from `plan.md`/`ship.md`/`review.md` into one `references/LIFECYCLE.md` (~2–3K tokens/session saved); commands reference it once.
- `orchestrator.md`: replace the ~80% duplication of `start.md` with "read `commands/start.md` base rules at session start" — one ~1.5K read, single source of truth, no drift.
- `plugin-policy.test.mjs` expectations updated alongside (it asserts on prompt contents).

### 1d. Budgets by default (one line, biggest absolute effect — targets the 2.2–3.2B Claude pool too)

`start.md`: session budget declaration (`--max-crossings`, default 5) becomes the **default for all sessions**, not just unattended. On exhaustion: refresh STATUS + checkpoint, summarize, recommend a fresh session. Mega-sessions become opt-in, not the ambient failure mode.

### 1e. Review rounds

Default cap 3; continuing past it is a DECISION (attended) or parks (unattended). Wire into `review.md` round accounting.

## WS-2 — Reviewer context bundle (was Phase 4)

Review/verify dispatches embed a deterministic bundle: candidate diff, changed-file list, evidence excerpts, relevant spec sections. Reviewers verify **from artifacts**, not implementer claims — independence preserved; the re-crawl (N rounds × full codebase) is eliminated.

Rules: bundle is **pinned to the candidate SHA**; any candidate change → bundle stale → regenerate, never patch. Bundle is a task-owned temporary artifact (cleanup per base rules). Keep sessions fresh/non-resumable — that property protects the sealed-candidate audit; the bundle is the correct fix for its cost.

## WS-3 — Usage policy + docs

README: the usage-policy table from §0, the OpenCode-host rationale line, and glossary entries. `PROJECT-CONVENTIONS.template.md`: same table, project-scoped. `start.md`: one classification hint — "If the task is exploratory or throwaway, recommend NOT using Airlock and stop." (The tool should say no to itself.)

## WS-4 — Launcher ride-alongs only (Phase 2 shrunk; full hardening deferred to 2.5)

Justification for the cut: external runtime = 5 dispatches / 24K tokens ever. Ship only what's nearly free while a session is already editing the manifest schema:

- Manifest `effort` allowlist: default medium; `ultra`/`high` require an explicit manifest field (wired into effective-identity proof).
- Default `wallClockMinutes: 45` (was 24h); higher requires explicit manifest field.
- **Deferred to 2.5** (pending actual usage): live turn/tool-event counting with kill-on-breach, incremental fail-fast checks, spiral detection. If implemented later: a budget kill is a *deliberate disruption* and must route through the existing recovery classifier (`no-commit` / `one-commit` / `indeterminate`) so a killed run still gets a clean baseline audit.

## Acceptance criteria

1. Guard denies: second checkpoint via Write; checkpoint-introducing Edit; ledger writes past hard cap. All fail-open behaviors preserved. Suites green (`guard`, `plugin-policy`; external-runtime green on Windows).
2. A scripted Full session on a test repo: ledger never exceeds one checkpoint; session ends at crossing budget with clean STATUS handoff.
3. A review dispatch containing the bundle completes without any repo-wide Grep/Read sweep (verify from the subagent transcript).
4. Prototype-classified request → orchestrator recommends not using Airlock.
5. README/PROJECT-CONVENTIONS carry the usage-policy table; release via the 2.3 release lane (Compact PR, DECISION to tag).

## Risks

| Risk | Mitigation |
|---|---|
| Ledger deny rules hit legacy ledgers (already >1 checkpoint) | Deny only *adding* checkpoints; hard cap message names the cleanup path; I6 cleans the known offender first |
| Budget-by-default annoys attended flow | It's a default, one flag overrides; summary+handoff makes session splits cheap |
| Bundle grows into its own token sink | Cap bundle size (e.g. 15K tokens); overflow → reviewer gets diff + file list only, and says so in evidence |
| Orchestrator downgrade (I2) degrades judgment | Explicitly sequenced after WS-1 measurement; drift history is the documented cost |

## Out of scope for 2.4

Full launcher hardening (2.5, usage-gated); OpenCode guard-equivalent port (decision deferred; Full work stays on Claude Code host); per-worker parallel contracts (still 2.5+); Managed Agents port (never, per 2.3 spec).

## Constraints

Repo changes uncommitted until user review unless asked; all machine-config edits (I1–I3) preceded by `.bak` backups; W33 baseline recorded (I4) **before** any I-action lands so the attribution is clean.
