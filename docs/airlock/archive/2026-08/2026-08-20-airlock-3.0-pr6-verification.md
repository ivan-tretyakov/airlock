### M1 — 🔴 Tag `v3.0.0` immediately after merging

`README.md:49` instructs:

```text
npm install --global github:ivan-tretyakov/airlock#v3.0.0
```

That tag does not exist until it is created. Between merge and tag, the only documented OpenCode install path fails. Tag in the same sitting as the merge, not "later".

### M2 — 🔴 Run `npm test` on Windows before tagging

This was in the first resolution's release checks ("Run the validated suite on Windows") and **silently disappeared from the second**. It should not have. The entire recovery layer is new since the last Windows run and is the most platform-sensitive code in the repo:

- `preservePaths` — `git stash push -- <paths>` with normalised forward-slash pathspecs
- `revertOutOfScope` / `recoveryPaths`
- `dirtyProductPaths` unborn-repo branch
- `normalizePath` backslash handling

The primary development host is Windows. One command:

```text
npm test
```

Record the result. If it is green, tag. If not, that is a pre-tag fix, not a 3.0.1.

## 3. 3.0.1 follow-ups (not merge-blocking)

### M3 — 🟡 `ownsPath` lost the case-folding 2.x had

2.x's guard folded case on win32 and darwin (`hooks/guard.mjs:292-293`). 3.0 compares path strings directly:

```
ownsPath(['src/a.js'], 'src/A.js')  ->  false
ownsPath(['Src/A.js'], 'src/a.js')  ->  false
```

On a case-insensitive filesystem — Windows and macOS, i.e. both machines in use — a plan declaring `owns: ["src/feature.ts"]` against a file git records as `src/Feature.ts` audits as out-of-scope. The task blocks, the delta is stashed, and the cause is invisible from the message. Restore the platform-conditional fold in `normalizePath`, or fold unconditionally in `ownsPath` only.

Suggested regression test: `owns: ["src/a.js"]`, builder writes `src/A.js`, assert in-scope on win32/darwin.

### M4 — 🟡 No bootstrap path for the OpenCode host

`npm pack --dry-run` ships:

```
.airlock/models.json  LICENSE  README.md  opencode.json  package.json
roles/{browser,builder,checker}.md  scripts/airlock.mjs
```

`.opencode/command/airlock.md` is **not** in the package, and `/airlock:setup` was deleted with the rest of 2.x. So a user installing the CLI globally still has to hand-create the OpenCode slash command in every project and hand-merge six agent bindings into that project's `opencode.json`. README §Hosts names the two host files but never says how the OpenCode one arrives.

This is the last gap between "works when dogfooding this repo" and "works where it ships" — the same shape as R4, one layer up. Options, cheapest first: (a) add an `airlock init --host opencode` step that writes both files; (b) add `.opencode/` to `files` and document a copy step; (c) document the copy explicitly in README.

### M5 — ⚪ `scripts/airlock.mjs` is committed `100644`

It is declared as `bin`. `npm install`/`npm link` set the executable bit from the shebang, so the shipped path works; only direct `./scripts/airlock.mjs` invocation from a clone fails. `git update-index --chmod=+x scripts/airlock.mjs` closes it.
