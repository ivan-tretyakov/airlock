## 2. New — 🟠 G1: upgrading from 3.0.1 breaks every OpenCode route, silently undocumented

A 3.0.1-shaped local config is version 1 and has **no `catalog` block**, because 3.0.1 had no such concept. Under 3.1 that config now fails on every OpenCode command:

```
$ airlock next --host opencode
OpenCode model openai/gpt-5.6-luna does not declare variant high in local catalog
```

The behaviour is correct and is exactly what I asked for in F2 — a route whose variant is not declared cannot be trusted, and OpenCode would silently discard it. But as an upgrade experience it is a hard break in a minor version, and two things are missing:

1. **No migration note.** README's `## Migration` section still covers only `airlock import` from a 2.x ledger. Nothing tells a 3.0.x user that their OpenCode routes will stop working until they add a catalog.
2. **The error does not say what to add.** Compare with the F6 fix, which prints the complete command. This one names a problem and no remedy — not the JSON shape, not where it goes, and not how to discover the legal variant names for a model.

That last point is the one I raised on the proposal and it is now load-bearing: the catalog is mandatory, so populating it correctly is a required step, and `opencode models <provider> --verbose` — the command that reveals the legal names, and the command your own variant gate used as evidence — appears nowhere in the README.

**Fix:** extend the message to the F6 standard, for example:

```
OpenCode model openai/gpt-5.6-luna does not declare variant high in local catalog.
Add it under catalog.opencode["openai/gpt-5.6-luna"].variants in <config path>.
Discover the legal names with: opencode models openai --verbose
```

and add an *Upgrading from 3.0.x* subsection to README Migration saying the catalog is now required for OpenCode routes. This is the item that will hit you personally on day one, on your own machine.

## 3. New — 🟡 medium

**G2 — two clocks inside one command.** `now()` returns the real wall clock and sets `task.startedAt`, `finishedAt` and `askedAt`; `commandNow()` is the injectable one (`AIRLOCK_NOW`) and drives route evaluation. §4.2's *"Capture one timestamp"* and the matching acceptance criterion are therefore not literally met. Production impact is microseconds and harmless.

The real risk is a latent test trap. Route recovery resolves from `task.startedAt` (`airlock.mjs:439`), which is real-clock. A future test that *starts* a task under `AIRLOCK_NOW` and then exercises recovery would resolve against whatever time the suite happens to run at — passing at 09:00 and failing at 11:00. The current recovery test sidesteps this by hand-writing `startedAt: "2026-08-24T07:00:00.000Z"`, which is correct but not self-evidently deliberate. Route `startedAt` through `commandNow()` as well, or leave a comment in the harness saying why it must be hand-written.

**G3 — the variant-discovery command is still undocumented.** README line 27 correctly states that OpenCode mappings *"including version 1 static mappings, declare each model's legal variants under `catalog.opencode`"*, but not how to find those names. One sentence naming `opencode models <provider> --verbose` closes it, and it belongs next to G1's migration note.

## 4. Token efficiency and wasted cycles

**Prompt surface 4,008 B against the 5,000 B ceiling** — up 164 B, all of it the explicit `--host opencode` on four lifecycle calls. That is the correct place to spend it: the alternative was relying on a default, which is what F1 was.

**The test-to-source ratio inverted back the right way.** Source 57,946 → 65,188 B (+12%); tests 29,630 → 43,346 B (+46%). Last round the source grew faster than the tests and the two untested behaviours were the two blockers. This round every finding arrived with a named regression test — 24 (host-scoped lifecycle), 25 (version 1 catalog), 26 (init bootstrap), 28 (pin expiry and status agreement), 35 (version 1 agent requirement).

**The efficiency lever now actually engages.** F2's fix means a static version-1 config can no longer generate an agent whose `variant` OpenCode silently discards, so per-role effort routing applies in the default setup rather than only under version 2. That was the point of the release and it was not true a round ago.

**Wasted cycles:** none of the remaining items stalls a run. G1 fails closed at the first command with a clear-enough message to diagnose in a minute, which is the cheap end of the scale.
