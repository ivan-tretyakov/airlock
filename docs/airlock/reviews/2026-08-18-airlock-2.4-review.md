## 2. Where the implementation exceeded the spec

**Ledger hygiene closed the hole the spec didn't name.** The obvious failure mode is enforcement that only fires while a dispatch contract is active — which would miss the checkpoint refresh that happens *after* the contract is deleted at the return audit, i.e. exactly the 68-checkpoint pattern. `guard.mjs:725-748` runs a **global hygiene block before contract discovery**, with a comment stating that reasoning, plus tests for the no-contract, malformed-contract, and expired-contract cases. The matcher is case-insensitive (`/^##[ \t]+resume[ \t]+checkpoint\b/gim`), so existing `## Resume Checkpoint` capitalisation is caught. Fails open on internal errors and on Edits it cannot model deterministically; Write below the cap remains allowed so a bloated ledger can still be shrunk. This is the difference between a rule and a mechanism.

**Review bundle is stricter than specified.** It derives the candidate diff and changed-file list from the repository and *rejects supplied inputs that do not match* (the spec only asked for a bundle pinned to the candidate SHA). Mandatory diff + file-list overflow **fails closed** rather than truncating evidence; optional sections record explicit omissions. SHA-256 over exact bytes; task-owned temporary artifact with cleanup.

**Host harness gate is correctly absolute.** Full work on a non-Claude host is `BLOCKED` — never downgraded to Compact, never executed inline, no override. That is the right reading of the spec's intent.

## 3. Recommendations

### R1 — 🔴 Bump the version (release blocker)

`.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json` are both still `2.3.0`. The marketplace serves from `main`, so merging without the bump ships 2.4 behaviour under a 2.3 label. Set both to `2.4.0` before opening the release PR.

### R2 — 🟡 Correct the token-savings accounting; prompt slimming did not deliver

Measured prompt surface, 2.3 → 2.4:

| File | 2.3 | 2.4 | Δ |
|---|---|---|---|
| `commands/start.md` | 14,118 | 16,190 | **+2,072** |
| `commands/plan.md` | 18,879 | 19,142 | +263 |
| `commands/ship.md` | 13,982 | 14,014 | +32 |
| `commands/review.md` | 9,054 | 9,725 | +671 |
| `agents/orchestrator.md` | 10,254 | 9,239 | −1,015 |
| `references/LIFECYCLE.md` | — | 5,527 | +5,527 |
| **Total** | **66,287** | **73,837** | **+7,550 (+11%)** |

The dedup was performed correctly — lifecycle, gate, waiver and checkpoint definitions are genuinely gone from the three commands and now live once in LIFECYCLE.md. The growth comes from new rules (host gate, budgets, hygiene, bundle) more than offsetting it. Two consequences:

- **WS-1c's "~2–3K tokens/session saved" does not exist.** Do not credit prompts in the measurement gate. WS-1b (bounded ledger reads) is the dominant term and is doing all the real work — which was always true; the accounting should say so.
- **`ship.md` is unchanged in size** (13,982 → 14,014), so the "3.5K × N Crossings re-injection" the plan targeted is untouched. If that cost matters, it needs its own pass: move the per-Crossing invariant prose into LIFECYCLE.md and leave `ship.md` as the procedure only.

### R3 — 🟡 Know the cost of the orchestrator → start.md indirection (accepted trade)

In 2.3, `--agent airlock:orchestrator` loaded one self-contained 10,254-byte file. In 2.4 it loads 9,239 bytes **and reads `start.md`'s 16,190 bytes** ≈ 25.4KB — roughly 2.5×. This followed a recommendation of mine that estimated a wash; start.md was larger than that estimate accounted for.

Recommendation: **keep it.** Single source of truth beats 80% duplication that drifts, and the cost is paid once per session, not per turn. But record it as a deliberate trade in the ledger rather than leaving it to be discovered. If it later proves material, the cheaper form is for `orchestrator.md` to read only the named sections it lists (Output, Classify, Host harness gate, Delegation, Unattended, Artifacts) rather than the whole file.

### R4 — 🟡 Fix the `selectedRoute: null` latent defect

When manifest validation fails, the blocked-summary builder (`run-external-agent.mjs:3675`) emits `selectedRoute: manifest ? {...} : null`. Any consumer reading `summary.selectedRoute.wallClockMs` then throws a TypeError instead of receiving a usable blocked summary — and route context is lost from the audit record precisely when a run failed. The two new wall-clock tests hit this.

Options, in preference order:
1. Populate `selectedRoute` from the parsed manifest whenever one was parsed, even if later validation failed (best — preserves audit context).
2. Null-guard the two new tests and document that `selectedRoute` is absent on pre-parse failures.

### R5 — ⚪ Confirm `run-external-agent` on Windows before the PR (verification gap, not a regression)

Linux results: 2.3 baseline 86 tests / 54 fail; 2.4 95 tests / 58 fail. The 9 new tests split 5 pass / 4 fail. **All four new failures share the pre-existing Linux environment cause** — verified by confirming 2.3's own happy-path test ("writer manifest accepts the strict structured sealing contract") already fails there, and that the new effort tests pass their first assertion and only fail after reaching the environment-sensitive validations block. This is not a regression.

But it means the effort-allowlist and wall-clock tests **have never been observed passing anywhere**. Run all four suites on the Windows host and record the result before opening the PR; R4 may need to land first for two of them to pass.

## 5. Scope discipline note

Worth recording as a positive: the implementing session shipped **only** the WS-4 ride-alongs (effort allowlist, 45-minute default) and left the deferred launcher hardening — live turn/tool-event counting, kill-on-breach, spiral detection, incremental fail-fast — untouched.
