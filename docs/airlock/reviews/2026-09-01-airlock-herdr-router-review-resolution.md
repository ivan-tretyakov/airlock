# Airlock Herdr Router Spec Review Resolution

**Date:** 2026-09-01
**Source review:** `2026-09-01-airlock-herdr-router-review.md`
**Resolved in:** `../specs/2026-09-01-airlock-herdr-router.md` (spec revision on `feat/herdr-router-4.0`; no product files changed)

## Resolved

| Finding | Resolution | Spec location |
|---|---|---|
| F1 | The trigger set is now defined **once**, as a three-class partition every failure falls into exactly once, and dispatch steps 9–10, the fallback section, and the reconcile delta all reference it instead of restating it. Class S (substrate: herdr daemon/socket/CLI failure) never advances and never blocks — `needs-reconcile` + retryable exit 69. Class E (executor start, provably before prompt delivery) is the only advancing class. Class P (anything at or after an accepted submission — stall, timeout, idle/exit, output) always routes to `needs-reconcile` for the human decision table. The step-9/step-10 contradiction is gone: step 10 now states that every post-acceptance signal is class P, and step 9's advance branch is restricted to class E. The reconcile idle/exited row's advance branch is **deleted** (the pane exists and the submission was accepted — class P by definition; the spec says so and why); only the orphan row advances, and only when class E is proven from persisted fields — the spec names them: `promptAttemptedAt: null` (a new field written before any submission call), record state `pane-created`/`agent-started`, a successful snapshot showing the agent gone, plus condition 2. Invariant 2's carve-out now cites the class-E definition. | §Invariants 2/8, §Dispatch steps 9–10, §Failure classes and fallback, §Reconciliation, §Failure modes |
| F2 | `agent_prompt_stalled` is removed from the qualifying list and placed in class P, with the herdr 0.8.2 help semantics quoted (a stall is reported only after an **accepted** submission) and an explicit statement that the 0.1.0 `agentPrompt` envelope classifying stall as `delivered: true` is **kept** — no silent inversion of the reused client. `fallback.test.mjs` asserts stall → `needs-reconcile`. The corroborated-stall alternative the review offered was not taken: a bounded pane read at stall time cannot prove the text will not act five seconds later, so fail-closed means never advancing on stall. | §Dispatch step 10, §Failure classes and fallback (class P), §Test plan |
| F3 | Substrate failures are class S, enumerated by the client's own codes (`herdr_not_installed`, `spawn_error`, herdr-call `timeout`, `cli_usage`, daemon/socket unreachable, failed snapshot): mark `needs-reconcile` with the diagnostic, exit 69 (`EX_UNAVAILABLE`, retryable), chain and task untouched — the next run retries the **same** candidate. At reconcile, a pane is treated as gone only on a **successful** snapshot that lacks it; the spec explicitly forbids reading `adoptPaneByName`'s `snap.ok === false` branch as "pane gone". A herdr restart mid-dispatch can therefore never burn the chain or block the task. | §Failure classes and fallback (class S), §Dispatch step 9, §Reconciliation preamble, §Failure modes |
| F4 | New §Workflow lock: a per-workflow advisory lock file (`<state-dir>/<session>/<workflowKey>/lock`, `O_EXCL`, `{pid, hostname, acquiredAt}`) held by every mutating verb for its whole run — extending the existing `state.mjs` atomic-rename pattern, which the spec now notes prevents torn files but not lost read-modify-write updates. Contention exits 69 having touched nothing; stale takeover on dead-pid-same-host or age > 2× `DEFAULT_TIMEOUT_MS`, single-winner retry. Advance idempotency: one atomic write carries `failures[]` + `candidateIndex` + `advanceCount`; the runner re-reads and compares `candidateIndex` under the lock before persisting and refuses a second advance from the same `fromAttempt`. The advanced-but-unlaunched attempt gets its own record state, `launch-pending` (replacing 0.1.0's `offered` misuse), whose dispatch/reconcile row is resume-the-same-candidate — never auto-advance fuel, so a crash loop cannot burn the budget. | §Workflow lock, §State records, §Reconciliation (`launch-pending` row), §Test plan |
| F5 | New **superseded** decision-table row keyed on the one condition that cannot be missed: a record beyond `offered` (proof our `start` once made the task `doing`) while the plan task is `todo` (an answered decision reverted it — rework additionally shows `startedAt: null` and the `reopened after …` note; an answered `needs-you` flips silently, so the status itself is the trigger). Settle as `settledAs: superseded`: close the plugin-owned pane only if a successful snapshot shows its agent exited/idle, verify the worktree clean, archive the record; the pin dies with it. Dirty worktree or working agent → the row reports and waits for the human (an explicit path, not a wedge). Dispatch evaluates the same row at step 1, so a reopened task re-dispatches in a single `dispatch` call. §Pinning's pin-death sentence now includes `superseded`, making its "later re-dispatch resolves a fresh chain" promise reachable. | §Reconciliation (superseded row), §Resolution algorithm and pinning, §Dispatch step 1, §Failure modes |
| F6 | Condition 2 now mandates the strict `detectNonce` parse (the `src/reconcile.mjs` regex with a verdict and non-placeholder summary) and forbids substring checks everywhere the rule applies, explaining why: the Path A typed REPORT line always contains the raw `AIRLOCK-RESULT <nonce>` string. Implementation note added that `src/render.mjs`'s `nonceSeenIn` (`.includes`) must be updated to match so `status`/`watch` rows agree with reconcile. The Path B `wait-output` premature match on the echoed message is documented as benign — a match only schedules reconciliation (Invariant 2). | §Failure classes and fallback condition 2, §Executors (Path B), §Plugin surface, §Test plan |
| F7 | The opencode agent-file check joins the binary probe and flag check as a per-candidate **pre-start skip** at step 4 (class `executor-preflight`, budget-free, remedy recorded in `failures[]`): the chain continues into a claude/codex candidate that needs no such file — the review's cross-executor point, accepted in full. Exit only when no candidate survives, and then exit 6 with every remedy printed; the mid-chain exit 4 is gone (code 4 retired). Invariant 7 reworded to per-candidate fail-closed. | §Executors (preflight), §Dispatch step 4, §Invariants 7, §Failure modes |
| F8 | Exit codes reassigned around airlock's: airlock 1 (generic) and 2 (`PARKED`) **pass through verbatim and are reserved** — the router never emits them for its own faults. Router usage → 64 (`EX_USAGE`), substrate/lock → 69 (`EX_UNAVAILABLE`), internal → 70 (`EX_SOFTWARE`), environment preconditions (herdr too old, 3.x CLI detected) → 78 (`EX_CONFIG`); 3/5/6 keep their non-colliding meanings. Full passthrough table documented in §Plugin surface and pinned by tests. | §Plugin surface (exit-code table), §Failure modes, §Test plan |
| F9 | Mapping-table row added: 3.x `effort: "none"` → candidate `effort` omitted (`null`), Path A eligible, with a per-row `MAPPED effort "none" -> omitted` notice. Rationale recorded: the 3.x catalog's `none` variant meant "pass no variant flag"; verbatim import would force Path B and emit `opencode run --variant none`. Added to the `import-routes.test.mjs` row list. (The worked example is unchanged — its mapped rows carry `medium`/`high`/`max`, never `none`.) | §import-routes mapping table, §Test plan |
| F10 | Every value interpolated into the Path B line — agent name, `model`, `effort`, prompt-file path — passes through `shellQuote` (single-quote wrapping with the `'\''` escape). Honest implementation note recorded: no named helper exists in 0.1.0 — the idiom lives inline in `pathBCommand` and covers only the prompt path — so the router hoists it into a named `shellQuote` in `src/dispatch.mjs` and applies it to all four values. The example command now shows the quoting. Regression test for shell metacharacters in `routing.json` values added. | §Executors (Path B), §Test plan |
| F11 | `needs-you` no longer settles the record or closes the pane: it is a pause, not a settlement. The record stays in flight (`needs-reconcile` with a new `parkedForHuman: <decision id>` field), the pane is left untouched, and the printed instruction is answer-then-reconcile; after the answer the task is `todo` and the superseded row (F5) settles the record with its exited/idle pane guard. Additionally, even `done`/`blocked` settles now close only plugin-owned panes whose agent state is exited or idle on a successful snapshot — a live working pane is never closed by any settle. | §Reconciliation (`needs-you` row), §State records (`parkedForHuman`), §Failure modes |
| F12 | "Advance" defined once: `pin.advanceCount` is the budget counter, distinct from `candidateIndex`. Only budget-consuming class-E advances (persisted `candidateIndex` increments after a post-start failure) increment it; step-4 pre-start skips move `candidateIndex` and append to `failures[]` (`fromAttempt: null`) but cost nothing. Condition 3 restated as `candidateIndex < candidates.length - 1 && advanceCount < 2`. This deviates from the review's simplest option (the pure 3.x `candidateIndex ≤ 2` bound) deliberately, and the spec records the deviation: an executor that never launched taught us nothing, and letting its absence exhaust the chain would waste the budget on non-events; the direction of the fix (explicit accounting) is what the finding required. | §Failure classes and fallback condition 3, §State records, §Dispatch step 4, §Test plan |
| F13 | Documented: `next.task` is the selected task **id string** (or `null`); `start.task` is the **full task object**; the step-6 mismatch check is explicitly pinned to the `agent` fields and warned away from comparing `task`. | §CLI contract (`next`/`start` bullets), §Dispatch step 6 |
| F14 | The absolute claim is corrected: `start` never re-emits the brief, and `next` re-emits it **conditionally** — when exactly one task is `doing`, with the `(resume)` marker. Retaining `taskText` remains mandated (the re-emission is conditional and not a reliable refresh), with the note that resume paths may legitimately refresh a lost brief via `next` when the condition holds. | §CLI contract (`next` bullet) |
| F15 | Detection re-keyed on **key presence** and moved to a side-effect-free probe: preflight runs `status --json` and refuses on a present `routes` key (3.x always emits it, even empty; 3.x `status` only reads pins via `routeFor` — verified — so the probe is pure), avoiding the 3.x `next` `ensureRoutePin` write entirely. The first real `next` keeps a belt-and-braces `"route" in response` check (3.x emits `route: null` when nothing is selected); if that late check fires, the stray offered pin is documented as harmless (five-minute TTL, router refuses before dispatching). | §CLI contract (4.0 detection), §Failure modes |
| F16 | The codex effort argv is pinned to two exact tokens: `-c`, then the single unquoted token `model_reasoning_effort=<effort>` — with the rationale (args after `--` are argv elements herdr passes with no shell; embedded quotes would reach codex literally) and a canonical expected form for `executors.test.mjs`. | §Executors table (codex row), §Test plan |
| F17 | All four items fixed. (1) The README edit instruction now quotes both actual sentences (lines 140 and 162) with their distinct replacements — they were never identical. (2) `--from` defaults to the full recovered 3.x chain: `AIRLOCK_CONFIG`, else `AIRLOCK_CONFIG_DIR`, else `$XDG_CONFIG_HOME/airlock`, else `~/.config/airlock` — so the importer reads exactly what 3.x read. ## Rejected

- None outright. Two findings were resolved with a recorded deviation from the review's suggested remedy rather than its letter: F2 (the "corroborated stall" alternative was declined as unprovable — stall is class P unconditionally) and F12 (the review's simplest `candidateIndex`-only bound was declined in favor of an explicit `advanceCount`, so pre-start skips of never-launched executors cannot exhaust the chain); both deviations are argued in the table rows above and in the spec text.
