# Airlock 4.0 Slim Core Spec Review Resolution

**Date:** 2026-09-01
**Source review:** `2026-09-01-airlock-4.0-review.md`
**Resolved in:** `../specs/2026-09-01-airlock-4.0-slim-core.md` (spec revision; no product files changed)

## Resolved

| Finding | Resolution | Spec location |
|---|---|---|
| F1 | The `UPGRADED` notice is written to **stderr in all modes**; `--json` output additionally carries a top-level `upgraded: true` field. The spec now states that stdout's first line remains `TASK`/`NOTHING TO DO`/`STARTED`/the JSON document, that the notice is emitted at most once per invocation including error paths (it fires at `readPlan` time, so it precedes the `PARKED` exit-2 error and post-upgrade validation errors), and adds `--json`-mode and `--unattended` notice tests. | §v3 read compatibility ("UPGRADED notice"), §Output shapes (JSON), §Tests |
| F2 | `roles/` is **not removed** — it stays the single source of role bodies for both hosts. `roleSource`/`roleBody` are kept unchanged (still reading `../roles/<role>.md`; `roles` is already in `package.json` `files`, so the npm-installed CLI can read it). `roleTools` moves to the deletion list — only `agentMarkdown` consumed it; the Claude agents are now the `roles/` files themselves and the OpenCode generation needs only `roleBody`. `init --host opencode` generates `.opencode/agent/airlock-<role>.md` from `roles/` exactly as 3.x `agentMarkdown` did minus `model`/`variant`: `description` + `mode: subagent` + `permission: edit: deny` for checker/browser, body from `roleBody`. | §Dispatch model, §Routing removal |
| F3 | The spec no longer says `plugin.json` "gains" entries: the existing `"agents": ["./roles/*.md"]` entries and paths are kept as-is; the only role-file change is the frontmatter rename `name: builder` → `name: airlock-builder` (etc.) so the plugin agent names match the emitted `AGENT airlock-<role>` line (today no agent named `airlock-builder` exists — the 3.x generated names carried model/effort suffixes and disappear). Added a pre-release acceptance step: install the plugin and confirm dispatch to the literal string `airlock-builder` resolves; if the host namespaces plugin agents, adjust the `AGENT` line format and record it. | §Dispatch model |
| F4 | The freeze wording now matches verified reality: `extensions/` is untracked and never committed; only `v3.0.0`/`v3.0.1` tags exist, so the README's `#v3.1.0` install line is already dangling. The freeze is restated as a **release precondition**: before 4.0 lands, commit `extensions/herdr` on the 3.x line and cut a `v3.1.x` tag containing it (which also repairs the dangling install tag). | §Extensions, §Versioning and migration (first bullet) |
| F5 | The version bump now enumerates every version-bearing surface, citing the 3.2-review convention that all manifests move together: `package.json`, `.claude-plugin/plugin.json`, `.claude-plugin/marketplace.json`, README install line, the OpenCode shim's own install line (all → `4.0.0`/`#v4.0.0`), and the test assertions that pin these strings. Decision recorded: the 4.0 shim drops the historical-tag sentence, because a 3.x global install cannot drive a v4 plan and advertising old tags would misdirect recovery. | §Versioning and migration, §Tests (last bullet) |
| F6 | `PROJECT-CONVENTIONS.template.md` is added to the rewrite scope with per-bullet instructions: the risk bullet becomes `expensive` guidance (`expensive: true` for irreversible/security-sensitive/migration work; `budget.maxExpensive` caps it), the local-routing bullet is deleted, and the builder-run-acceptance and consolidated-checker bullets are kept with risk-level references reworded. | §README and template rewrite |
| F7 | The Claude customization path no longer points at plugin-managed files: the user creates a same-named override agent — project `.claude/agents/airlock-<role>.md` or user `~/.claude/agents/airlock-<role>.md` — with a `model:` line, which the host resolves in preference to the plugin copy. The spec states explicitly that the 3.x shadow guard is removed **deliberately** (shadowing flips from routing-integrity violation to the intended mechanism) and adds a pre-release acceptance step to verify the host's actual precedence order and record it in the README. | §Dispatch model ("Model customization") |
| F8 | Deletion list completed: `openCodeConfigDir` (with `OPENCODE_CONFIG_DIR` — deleted rather than retained, because the 4.0 OpenCode bootstrap writes only into the project's `.opencode/`, never the user config dir), `claudeAgentsDir` (with `AIRLOCK_CLAUDE_AGENT_DIR`), `configText`, `importLedger` (the `import` command is now also named in the deletion list), `roleTools` (per F2), and the now-unused `unlinkSync`/`readdir` imports. | §Routing removal |
| F9 | Exact 4.0 output shapes specified in a new section: `render --md` table header becomes `\| ID \| Task \| State \| Role \|` (Route column replaced by role); `statusText` DOING rows become `<id> <title> <role> <duration>` and NEXT rows `<id> <title> <role>`; `status --json` returns `{text, plan}` with the `routes` array deleted outright and no `agent` field (static agents are derivable from `plan`) — the old blanket "drops route, keeps agent for status" phrasing is gone; `next`/`start` return `{text, task, agent}`. | §Output shapes |
| F10 | Hash-guard sentence corrected: `LEGACY_OPENCODE_COMMAND_HASHES` currently holds only the two 3.0-era hashes; the hash of the packaged 3.1 shim (`9201872f…`, with `\r\n` normalization) must be **added** so unmodified 3.1 shims auto-upgrade instead of hitting the manual-merge error. The auto-upgrade test is required to use the real packaged 3.1 shim bytes, not a fixture. | §Host shims, §Tests |
| F11 | Both edges decided: explicit `expensive: false` is **accepted** as equivalent to absent (less trappy for hand-authors and generators that always emit the field; non-boolean values rejected with `task <id> expensive must be a boolean`), and a residual `risk` field on a v4 task is **rejected** fail-closed with `task <id> risk was removed in v4; use expensive: true for critical-cost tasks` — an explicit check, since `validatePlan` otherwise ignores unknown fields and a hand-migrated plan would silently lose budget protection. Both cases added to §Tests. | §Plan schema v4, §Tests |
| F12 | `--host` is **accepted and ignored** as a deprecated no-op on all non-`init` commands, so preserved/customized 3.x shims (which pass it to every verb) keep working; `AIRLOCK_HOST` is simply no longer read (setting it has no effect). Help documents `--host` under `init` only. The 4.0 shims themselves drop `--host` from coordinator verbs, with test assertions updated accordingly. | §Command surface, §Host shims, §Tests |
| F13 | Persistence semantics made explicit: every state-mutating command (`start` — including the resume branch, which gains a `writePlan` when `readPlan` upgraded — `done`, `block`, `ask`, `answer`) persists v4; read-only commands (`next`, `status`, `audit`, `render`) never rewrite and re-emit the stderr notice each run; the spec states deliberately that a read-only-forever plan stays v3 on disk and that this is acceptable. `start` output is now specified (`STARTED <id>` / `STARTED <id> (resume)` + `AGENT airlock-<role>`), with the resume branch called out as the v3-migration path (its 3.x pin vanished with router state), and a v3-resume test added. | §v3 read compatibility ("Persistence"), §Output shapes, §Tests |
| F14 | The `(risk: critical -> expensive on <ids>)` suffix is emitted **only** when at least one task actually mapped; the base notice carries no parenthetical otherwise. A v3 task already carrying an `expensive` field is rejected by the upgrade function, fail-closed: `task <id> has both risk and expensive; a v3 plan must not carry expensive`. Both behaviors added to §Tests. | §v3 read compatibility |
| F15 | The chained equality is reworded to `isExpensive(task)` returns `task.expensive === true`. | §Plan schema v4 |
| F16 | Ceiling claim corrected: the 5,000-byte test already sums `commands/` + `roles/` + `.opencode/command/` and its composition is unchanged (no `roles/`→`agents/` rename after F2); the 800-byte per-role ceiling stays, with the note that the `name:` rename adds ~8 bytes per file. Shim marker assertions specified: keep `unattended`, flip `fallback <id>`/`--class <class>`/`Never fallback after any child result` from presence to absence, drop the per-verb `--host` matches and assert their absence, move the install-line assertions to `#v4.0.0`. | §Host shims, §Tests |

## Rejected

- None. All sixteen findings were accepted; F8's `openCodeConfigDir` question (retain vs. delete) was resolved toward deletion because the surviving OpenCode bootstrap writes only project-local files.
