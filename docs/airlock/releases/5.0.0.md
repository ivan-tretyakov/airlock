# Airlock 5.0.0

- Date: 2026-09-05
- Series: Airlock 5.0 — spec 1 uncommitted plan state (`2026-09-04-airlock-5.0-plan-state.md`), spec 2 headless runner (`2026-09-04-airlock-5.0-run.md`), spec 3 removals (`2026-09-04-airlock-5.0-removals.md`)
- Breaking. The major version exists because dispatch surface was deleted, not extended.

## What was removed

5.0 leaves one dispatch path, `airlock run`, and deletes everything that served host-side dispatch:

- The bundled Claude role agents and the `agents` list in `.claude-plugin/plugin.json`. The plugin now ships only the `/airlock` command and the CLI; the runner reads the three role files in `roles/` directly and no host agents are registered anywhere.
- The OpenCode bootstrap: `init --host opencode`, the `.opencode/command/airlock.md` shim it wrote, the `.opencode/agent/airlock-*.md` files it generated, and the hash-guarded shim upgrade with its legacy-hash fixtures (`scripts/fixtures/`). The `.opencode/` adapter directory in the repository is gone.
- The `--host` flag on every verb. It is not deprecated and ignored — it is rejected as an unknown flag, as is any other unknown flag on any verb.
- The Herdr extension (`extensions/herdr/`): a dozen source files, tests, and evidence for a Linux-only pane-driving design that was abandoned when the headless runner landed. Its specs and reviews are archived, not deleted: `docs/airlock/archive/2026-09/` holds the Herdr adapter spec, the Herdr router spec, and their reviews.

What remains: the CLI with the `run` verb, the three role files, the `/airlock` command file, `render --md` for the plan table, and the validation, scheduling, audit, and commit machinery unchanged.

## What 5.0 already brought

- **Plan location (spec 1).** `init` writes the plan to `.airlock/plan.json` and adds `.airlock/` to `.git/info/exclude` per clone, so the plan never lands in a merge request and disappears with the worktree. A plan joins a task commit only when git already tracks it; legacy locations (repository root, `docs/airlock/`) keep working. A reporting-only checker now completes through an empty commit carrying the `Airlock-Task` and `Evidence` trailers.
- **The routing file (spec 2).** `~/.airlock/routing.json`, schema version 1: `bindings.<role>.<tier>` for each of builder/checker/browser and default/expensive, each slot exactly `{ "executor": "claude" | "codex" | "opencode", "model": "...", "effort": "..." }` with `effort` optional, plus an optional top-level `timeoutMinutes` (default 30). Unknown keys are rejected; a missing slot fails closed with the JSON path named.
- **`airlock run`.** One invocation executes the next runnable task end to end — routing lookup, headless executor spawn with the role body plus brief on stdin, `EVIDENCE:` parsing, audit, commit or block. `--all` loops; `--dry-run` prints the resolved command without launching. Any executor failure blocks the task with the cause and stops the run; nothing retries and nothing falls back.

## Migrating from 4.x

1. Install the CLI globally from the tag:

   ```text
   npm install --global github:ivan-tretyakov/airlock#v5.0.0
   ```

2. Write `~/.airlock/routing.json` (see README §Running). This file replaces every per-role model preference you previously expressed through host agent files: one slot per role and tier, executor, model, and optional effort.
3. Your `init --host opencode` invocations stop working: `--host` is now rejected as an unknown flag. Bootstrap nothing — `airlock run` reads the roles from the package and spawns the executor itself.
4. Remove the files a 4.x bootstrap wrote into your projects: `.opencode/agent/airlock-*.md` and `.opencode/command/airlock.md`. They are inert under 5.0 but will confuse any executor that still lists them as agents.
5. If you used the Herdr router from 4.x, uninstall the plugin from Herdr; the runner replaced it.

Plans carry over unchanged: the schema is still `airlock.plan/v4`, a committed plan keeps joining task commits, and a fresh `init` writes the untracked `.airlock/plan.json`.

## Operator checklist

Manual, on each machine that ran 3.x or 4.x; nothing here is automated because it touches files outside any repository:

- [ ] Delete the generated `airlock-*` agent files in the user-level OpenCode agents directories: the plural `agents/` and the legacy singular `agent/` inside your OpenCode config directory (typically `~/.config/opencode/`).
- [ ] Delete the generated `airlock-*` agent files in the user-level Claude agents directory (typically `~/.claude/agents/`), including any `airlock-<role>-<model>-<effort>` files from 3.x routing.
- [ ] Remove the 3.x fallback backup of the OpenCode config — the `.bak` copy of `opencode.json`/`opencode.jsonc` taken before a 3.x route or fallback edit — if it is no longer wanted.
- [ ] Optional: delete obsolete 3.x routing artifacts (user and project `models.json`, `router-state.json`) that 4.x already ignored.
